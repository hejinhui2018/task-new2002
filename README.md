# 移液方案预演工具（Pipette Planner）

上机前在浏览器里预演 96 孔板移液方案，逐步核对**孔内体积、浓度与污染风险**：

- 内置 **200 µL/孔** 的 96 孔板与 **A1 → A8 二倍稀释**默认方案
  （A1：200 µL / 100 µM 样本；A2–A8：各 100 µL 稀释液；逐级混匀后转移 100 µL；
  最后从 A8 弃去 100 µL，各孔终体积 100 µL、浓度 100 → 0.78125 µM）。
- 步骤可**增加、删除、拖动排序、行内编辑**，每步可指定**新吸头**或**复用组**；
  工具栏支持 **撤销 / 重做**（按钮或 Ctrl/Cmd+Z、Ctrl+Shift+Z）。
- 任何编辑后都从初始板**重新整盘计算**，绝不保留旧结果。
- **单步前进 / 后退**与**连续播放**；孔板以颜色（蓝色顺序色阶 = 浓度）和数值
  （体积 µL / 浓度 µM）显示，悬停可看分析物总量、混匀状态与样本谱系。
- 右栏 **复用吸头残留（当前帧）** 面板逐帧显示每支复用吸头携带的残留样本与
  接触来源孔；它与污染判定、失败解释读取同一份 `tipFrames` 快照，不会出现
  “面板干净却被拦 / 面板有残留却放行”的不一致。
- 出现 **吸空、溢出（>200 µL）、未混匀转移、复用吸头跨样本带入** 时，
  **停在首次失败步骤**，红色高亮受影响孔并给出中文原因；此前的有效状态仍可单步回看。
  首错冻结只由重新仿真解除，撤销 / 重做 / 回看都不能绕过它。
- 实时**质量守恒账**：板上 + 废液 = 初始 + 储液加入（体积与分析物分别核对）。
- 方案自动保存在浏览器 **localStorage**，刷新不丢失；支持明 / 暗主题。

## 运行方式

需要 Node.js ≥ 18。

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器（默认 http://localhost:5173）
```

其他命令：

```bash
npm test           # 运行全部测试（Vitest，一次性）
npm run test:watch # 测试监听模式
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 预览生产构建
```

## 仿真模型说明

### 状态记账

每孔记录：

| 字段 | 含义 |
|---|---|
| `volume` | 体积 (µL) |
| `amount` | 分析物总量 (pmol = µM·µL)，浓度 = `amount / volume` |
| `mixed` | 是否已混匀；**向已有液体的孔加液 / 受液后变为 false** |
| `samples` | 样本谱系（样本标识集合） |

- 从空孔加入均匀液体视为天然均匀，无需显式混匀；
- 两种液体合并后必须先混匀才能作为吸样来源（否则报 **未混匀转移**）。

### 步骤类型

| 类型 | 语义 |
|---|---|
| 加液 dispense | 从储液池向孔中加入指定体积 / 浓度的液体（浓度 0 = 稀释液；>0 需填样本标识） |
| 转移 transfer | 从来源孔吸指定体积打入目标孔 |
| 混匀 mix | 标记该孔已混匀 |
| 弃液 aspirate | 从孔中吸指定体积排入废液缸 |

每步的检查顺序为：**参数合法性 → 吸头污染 → 来源孔混匀 → 来源孔余量（吸空）
→ 目标孔容量（溢出）**。任一不通过即在该步中止，不产生任何状态变更。

### 样本身份（谱系）判定规则

每孔的 `samples` 是孔内液体携带的样本标识集合，按液体流动传播，与体积 / 浓度账目分开记账：

1. **加液**：加入浓度 > 0 的液体时，把该步的 `sampleId` 并入目标孔；纯稀释液（浓度 0）
   不携带任何样本身份。
2. **转移**：被吸走的液体携带**吸样一刻**来源孔的全部身份，并入目标孔谱系。
   - **部分转移**：来源孔仍有液体，继续保留原身份。
   - **整孔转移（吸取量恰好清空源孔）**：身份随整孔液体离开——源孔变空、谱系清空，
     目标孔（即使原本是空孔）仍继承全部身份，分析物总量一分不少地落到目标孔。
3. **弃液**：被弃液体的身份随液体进废液；整孔弃液后源孔变空、谱系清空。
   **但身份不会因此从系统中消失**：若使用复用吸头，身份已在接触一刻记入吸头残留（见下）。
4. **空孔受液**视为天然均匀（`mixed = true`）；与孔内旧液合并后必须重新混匀。
5. 已清空的源孔可以装入另一份样本重新开始，新旧谱系互不串。

### 吸头残留与跨样本污染判定

- **新吸头**：一次性，不携带任何残留。
- **复用组**：同名复用组视为共用同一支吸头。残留按「接触来源孔 → 接触一刻该孔的样本身份」
  记账，并在每个成功步骤后写入与孔板帧对齐的 `tipFrames` 快照。
  - **记录时机是吸头接触孔内液体的一刻**，身份当场快照；之后该来源孔即使被整孔
    转移 / 弃液清空，残留记录依然保留，失败解释仍能指出样本标识与来源孔。
  - **只接触稀释液（`amount = 0`）不留残留**；先分装稀释液、再接触样本的顺序是安全的。
- **跨样本带入判定**：复用吸头进入某孔的一刻（检查先于混匀、余量、容量检查），
  若残留中存在该孔谱系**不含有**的样本标识，即判 `contamination` 并在该步中止，
  失败孔列表首项为被带入孔，其余为携带这些身份的来源孔（去重）。
  - 进入空孔、或进入只含另一份样本（如 S2）的孔都会被拦截。
  - 沿正常连续稀释链向下游走是安全的：下游孔通过正式受液已含有上游样本身份。
  - 整孔转移 / 整孔弃液后复用吸头仍带残留——这正是“用同一组吸头把一份样本
    整孔转走、再去碰另一份样本”必须报警的情形。

> 注意：真实操作中若用同一支吸头在接触样本后再向孔中打入稀释液，残留会在
> 正式转移之前进入该孔——工具同样会拦截。请先用干净吸头分装稀释液。

## 项目结构

```
src/
  engine/            纯 TypeScript 仿真引擎（无 React 依赖）
    types.ts         类型定义
    plate.ts         96 孔板工具、浓度计算
    defaults.ts      内置 A1→A8 方案
    simulator.ts     逐步仿真、四类失败检测、质量守恒账、样本谱系与吸头残留
  components/
    WellPlate.tsx    孔板网格（颜色 / 数值 / 悬停提示 / 高亮）
    StepList.tsx     步骤增删、拖拽排序、行内编辑
    TipResidue.tsx   当前帧复用吸头残留面板（读 tipFrames）
    colorScale.ts    浓度 → 蓝色顺序色阶（明 / 暗双主题）
  state/
    storage.ts       localStorage 持久化与数据校验
    history.ts       步骤序列的撤销 / 重做历史（纯 reducer）
  App.tsx            播放控制、撤销重做、失败面板、残留面板、守恒账面板
test/
  engine.test.ts     引擎测试（守恒 / 稀释 / 重排 / 容量 / 吸头 / 身份回归）
  app.test.tsx       jsdom 下的 App 测试：现场污染场景、拖拽重排、撤销重做、localStorage
  render.test.tsx    App 整树渲染冒烟测试
```

## 测试覆盖

`npm test` 覆盖需求中的关键性质（共 47 个用例）：

- **质量守恒**：默认方案与随机组合下，板上 + 废液恒等于初始 + 储液加入
  （体积和分析物分别核对）；失败前缀上也平账。
- **连续稀释**：严格二倍浓度链 100, 50, 25, …, 0.78125 µM；
  各孔终体积 100 µL；中间帧的来源减半 / 目标合流与未混匀标记正确。
- **步骤重排**：把混匀与转移调换、删除关键混匀步骤会在正确步骤报
  `unmixed` 并停止；调换加液顺序后按新顺序给出新中间帧（不保留旧结果）；
  整孔转移后复用吸头重回已清空源孔的顺序报 `contamination`，把混匀挪到转移之前则通过。
- **容量限制**：单次 / 累计加液、转移进液超过 200 µL 报 `overflow`；
  吸取量超过余量报 `empty`；恰为 200 µL 合法。
- **吸头状态**：新吸头无残留；复用组沿稀释链安全；跨样本（S1→S2 孔 / 空孔）
  报 `contamination`；不同组互不影响；只接触稀释液不构成污染；空组名等非法输入报 `invalid`。
- **整孔清空身份回归**：恰好清空源孔的转移 / 弃液，下游谱系与分析物不丢、
  复用吸头残留保留；现场场景（整孔转移 S1 后复用吸头进入 S2 孔）被拦截，
  失败前各帧（含谱系、残留、守恒账）完整可回看；部分转移、连续稀释、
  只接触稀释液等合法流程行为不变。
- **App 集成（jsdom）**：孔详情 / 残留面板 / 失败解释同帧一致且首错冻结；
  拖拽重排使失败消失 / 撤销后恢复；删除步骤的撤销与重做；localStorage 恢复与损坏回退。
