# 移液方案预演工具（Pipette Planner）

上机前在浏览器里预演 96 孔板移液方案，逐步核对**孔内体积、浓度与污染风险**：

- 内置 **200 µL/孔** 的 96 孔板与 **A1 → A8 二倍稀释**默认方案
  （A1：200 µL / 100 µM 样本；A2–A8：各 100 µL 稀释液；逐级混匀后转移 100 µL；
  最后从 A8 弃去 100 µL，各孔终体积 100 µL、浓度 100 → 0.78125 µM）。
- 步骤可**增加、删除、拖动排序、行内编辑**，每步可指定**新吸头**或**复用组**。
- 任何编辑后都从初始板**重新整盘计算**，绝不保留旧结果。
- **单步前进 / 后退**与**连续播放**；孔板以颜色（蓝色顺序色阶 = 浓度）和数值
  （体积 µL / 浓度 µM）显示，悬停可看分析物总量、混匀状态与样本谱系。
- 出现 **吸空、溢出（>200 µL）、未混匀转移、复用吸头跨样本带入** 时，
  **停在首次失败步骤**，红色高亮受影响孔并给出中文原因；此前的有效状态仍可单步回看。
- 实时**质量守恒账**：板上 + 废液 = 初始 + 储液加入（体积与分析物分别核对）。
- 方案自动保存在浏览器 **localStorage**，刷新不丢失；支持明 / 暗主题。

## 运行方式

需要 Node.js ≥ 18。

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器（默认 http://localhost:5173）
```

其他命令：

```bash
npm test           # 运行全部测试（Vitest，一次性）
npm run test:watch # 测试监听模式
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 预览生产构建
```

## 仿真模型说明

### 状态记账

每孔记录：

| 字段 | 含义 |
|---|---|
| `volume` | 体积 (µL) |
| `amount` | 分析物总量 (pmol = µM·µL)，浓度 = `amount / volume` |
| `mixed` | 是否已混匀；**向已有液体的孔加液 / 受液后变为 false** |
| `samples` | 样本谱系（样本标识集合），随液体走，详见下节 |

- 从空孔加入均匀液体视为天然均匀，无需显式混匀；
- 两种液体合并后必须先混匀才能作为吸样来源（否则报 **未混匀转移**）。

### 样本身份（谱系）判定规则

- `加液` 浓度 > 0 时把样本标识并入目标孔谱系；浓度 0（稀释液）不改变谱系。
- `转移` 按**被吸出的那份液体**把来源孔当前谱系并入目标孔——即使这一步
  恰好把源孔抽空，下游孔仍完整保留来源样本身份。
- 孔被抽空（体积归零）即为空孔：谱系随之清空，空孔不"含有"任何样本；
  已随液体离开的谱系由下游孔与吸头残留各自保留。
- 孔详情（悬停提示）、历史帧与污染判定读取的都是这同一份 `samples` 状态。

### 步骤类型

| 类型 | 语义 |
|---|---|
| 加液 dispense | 从储液池向孔中加入指定体积 / 浓度的液体（浓度 0 = 稀释液；>0 需填样本标识） |
| 转移 transfer | 从来源孔吸指定体积打入目标孔 |
| 混匀 mix | 标记该孔已混匀 |
| 弃液 aspirate | 从孔中吸指定体积排入废液缸 |

每步的检查顺序为：**参数合法性 → 吸头污染 → 来源孔混匀 → 来源孔余量（吸空）
→ 目标孔容量（溢出）**。任一不通过即在该步中止，不产生任何状态变更。

### 吸头与跨样本污染

- **新吸头**：一次性，不携带任何残留。
- **复用组**：同名复用组视为共用同一支吸头。吸头接触含分析物的孔后，
  会记录该孔的**样本标识**；再次进入另一孔时，若该孔不含有这些样本
  （如进入不相干的另一组样本孔或空孔），判定为**跨样本带入**并中止。
- 沿正常连续稀释链向下游走是安全的：下游孔通过正式受液已获得上游样本谱系，
  不构成污染。只接触过稀释液的吸头不留下样本残留。

**吸头残留按"接触那一刻的液体"记账：**

- 吸头每次接触板孔时，若所接触的液体含分析物（`amount > 0`），就把
  **该液体当时携带的**样本谱系与所在孔记入残留。对吸样步骤（转移 / 弃液）
  而言即吸出物——因此**整孔转移、整孔弃液把源孔抽空后，吸头上的样本身份
  依然完整**，随后进入另一份样本孔会被正常拦截。
- 只接触稀释液（无分析物）的吸头不留样本残留。
- 残留记录同时保存"每个样本来自哪些孔"（`tipFrames` 中的
  `residueSampleSources`），在接触瞬间写入；失败解释中的来源孔列表直接
  取自这份记录，即使来源孔随后被抽空 / 改写也不会指错位置——复用吸头
  检查、孔详情、历史帧与失败解释使用的始终是同一份状态。
- **首错冻结**：首个失败步骤不产生任何状态变更，其前的板帧 / 吸头帧 /
  废液帧全部保留，可单步回看；任何检测逻辑都不会跳过首错继续执行。

> 注意：真实操作中若用同一支吸头在接触样本后再向孔中打入稀释液，残留会在
> 正式转移之前进入该孔——工具同样会拦截。请先用干净吸头分装稀释液。

## 测试覆盖

`npm test` 覆盖需求中的关键性质：

- **质量守恒**：默认方案与随机组合下，板上 + 废液恒等于初始 + 储液加入
  （体积和分析物分别核对）；失败前缀上也平账。
- **连续稀释**：严格二倍浓度链 100, 50, 25, …, 0.78125 µM；
  各孔终体积 100 µL；中间帧的来源减半 / 目标合流与未混匀标记正确。
- **整孔清空回归**：恰好抽空源孔的转移 / 弃液后，下游孔保留样本谱系、
  吸头残留仍记录样本身份；随后进入另一份样本孔（或空孔）报
  `contamination`，失败解释指名已被抽空的残留来源孔；只接触稀释液的
  整孔操作不留残留，部分转移行为不变。
- **步骤重排**：把混匀与转移调换、删除关键混匀步骤会在正确步骤报
  `unmixed` 并停止；调换加液顺序后按新顺序给出新中间帧（不保留旧结果）；
  调换污染相关步骤后，跨样本判定按新顺序在正确步骤报出。
- **历史帧与撤销重做**：首错冻结，失败步骤不产生帧、后续步骤不执行；
  失败前的板帧 / 吸头帧 / 废液帧与逐步前缀仿真逐一一致，后续步骤不改写
  历史帧；删除再恢复步骤（撤销 / 重做）后逐帧复现相同结果。
- **容量限制**：单次 / 累计加液、转移进液超过 200 µL 报 `overflow`；
  吸取量超过余量报 `empty`；恰为 200 µL 合法。
- **吸头状态**：新吸头无残留；复用组沿稀释链安全；跨样本（S1→S2 孔 / 空孔）
  报 `contamination`；不同组互不影响；只接触稀释液不构成污染；空组名等非法输入报 `invalid`。
- **localStorage**：保存 → 读取回环后步骤（含复用组）逐一相等，恢复的步骤
  复现相同的污染检测与谱系；无数据 / JSON 损坏 / 结构非法时回退默认方案。
